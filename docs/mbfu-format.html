Формат образа .mbfu

Редакция от 18 ноября 2026 года.

.mbfu — контейнер для образа диска: фиксированный заголовок на 126 байт, сжатие zlib и контроль целостности SHA-256. Формат описан публично, чтобы образы можно было читать и проверять без запуска программы.

Зачем свой контейнер

  • Потоковая запись. Образ можно распаковывать сразу на устройство, не занимая места на диске: заголовок фиксированного размера, дальше — один поток deflate.
  • Проверка целостности. SHA-256 считается по несжатым данным и проверяется как при распаковке, так и после записи на флешку.
  • Метаданные. В заголовке лежит исходное имя файла и тип носителя, поэтому по образу видно, откуда он снят.
  • Экономия. Образы MS-DOS сжимаются в разы: мегабайты пустого пространства и повторяющихся секторов убирает deflate.

Структура файла

Заголовок — 126 байт, все многобайтные числа little-endian, выравнивания нет. Формат в терминах struct: <8sHBBHQQ32s64s.

СмещениеРазмерПолеЗначение
08magicMBFUIMG\x01
82versionuint16, сейчас 1
101image_typeuint8: 0 — сырой образ, 1 — дискета, 2 — жёсткий диск
111compressionuint8: 1 — zlib (deflate)
122reserveduint16, всегда 0
148raw_sizeuint64, размер несжатого образа в байтах
228data_sizeuint64, размер сжатого потока в байтах
3032sha256SHA-256 несжатого образа
6264nameимя исходного файла, ASCII, дополнено нулями

Сразу за заголовком идёт один поток zlib, длина которого равна data_size. Других полей, оглавлений и выравниваний нет — поэтому файл можно читать последовательно, не зная его размера заранее.

Как прочитать образ

Минимальный пример на Python — только стандартная библиотека: 

import hashlib, struct, zlib

HDR = "<8sHBBHQQ32s64s"
SIZE = struct.calcsize(HDR)          # 126

def read_header(path):
    with open(path, "rb") as f:
        buf = f.read(SIZE)
    magic, ver, itype, comp, res, raw, dsize, digest, name = struct.unpack(HDR, buf)
    if magic != b"MBFUIMG\x01":
        raise ValueError("not an .mbfu image")
    return {"version": ver, "image_type": itype, "compression": comp,
            "raw_size": raw, "data_size": dsize,
            "sha256": digest.hex(),
            "name": name.rstrip(b"\0").decode("ascii", "replace")}

def extract(src, dst):
    info = read_header(src)
    h = hashlib.sha256()
    with open(src, "rb") as f, open(dst, "wb") as out:
        f.seek(SIZE)
        dec = zlib.decompressobj()
        while True:
            chunk = f.read(1 << 20)
            if not chunk:
                break
            data = dec.decompress(chunk)
            if data:
                h.update(data)
                out.write(data)
        tail = dec.flush()
        if tail:
            h.update(tail)
            out.write(tail)
    if h.hexdigest() != info["sha256"]:
        raise ValueError("checksum mismatch")
    return info

Проверка хэша обязательна: повреждённый или обрезанный файл распакуется без ошибки zlib, если обрезан по границе блока, и только SHA-256 это поймает.

Что программа принимает на вход

  • .mbfu — собственный контейнер;
  • .img, .ima — сырые образы дискет и дисков;
  • .vhd, .vfd — образы виртуальных машин и дискет.

Сырые образы пишутся на носитель как есть; .mbfu распаковывается по ходу записи, а после завершения хэш сверяется с заголовком.

Ограничения

  • образ больше 4 ГБ не откроется в DOSBox 0.72 — он молча показывает пустой диск, поэтому редактор образов ограничен этим размером;
  • запись на флешку возможна и для образов больше 4 ГБ, но DOS-раздел всё равно ограничен FAT16;
  • имя файла в заголовке — ASCII; кириллица в имени заменяется безопасными символами, сам образ от этого не страдает.

Правовой статус

Описание формата открыто: вы можете реализовать чтение .mbfu в своём инструменте. Сама программа MBFUTool 2.x — проприетарная, её исходный код не публикуется; условия — в лицензионном соглашении.

Версия формата 1. При изменении структуры заголовка поле version будет увеличено, а старые файлы продолжат читаться.
