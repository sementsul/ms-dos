Secure Boot and CSM on ASUS and MSI boards

Two firmware switches decide whether a modern board will boot a DOS USB stick: Secure Boot and CSM. Their names and locations differ between ASUS and MSI, and on both brands the CSM entry can disappear once the board is set to a pure UEFI boot mode.

ASUS: Advanced Mode and the Boot menu

On ASUS boards the relevant settings sit in Advanced Mode, which you reach by pressing F7 in the initial setup screen. Open the Boot tab and look for CSM; in the same area, Secure Boot holds an OS Type option. Setting OS Type to Other OS relaxes the signature requirement, which is what a DOS-era loader needs. CSM must be enabled for a legacy boot sector to run at all. If the CSM item is missing, the board is in a UEFI-only state.

MSI: Windows OS Configuration

On MSI boards the same pair lives under Advanced in the Windows OS Configuration submenu. Secure Boot is switched off there, and CSM is enabled in the same screen or in the boot-related submenu next to it. Some layouts place CSM on a separate Boot page. After changing either option, save and exit; the board re-enumerates boot devices on the next power-on.

What each switch does

Secure Boot is a firmware policy: the bootloader must carry a signature that the firmware trusts. A DOS boot sector has no such signature, so with Secure Boot on, the firmware refuses to hand control to it. CSM (Compatibility Support Module) is the opposite kind of switch: it keeps legacy interrupt and device services alive and lets the firmware read an MBR partition table and jump into a 512-byte boot sector. Enabling CSM does not disable Secure Boot, and disabling Secure Boot does not enable CSM. Treat them as two independent conditions that both have to be right.

Why CSM can be hidden

Firmware hides the CSM entry when the boot mode is set to pure UEFI. On many boards this happens automatically once the boot list contains only UEFI entries, or after Boot Mode is changed to UEFI only. The way back is to switch the boot mode to CSM or legacy support first, then reopen setup: the CSM and legacy USB options reappear. On some models the CSM line only shows up after Fast Boot is disabled. Menu names vary by model and firmware build, so follow the tab names rather than an exact sequence.

When the DOS stick is not in the boot menu

Check the stick before blaming the board. The image must have been written to the device, not copied as a file; the stick needs an MBR partition table with one active partition holding the DOS boot sector; FAT16 is the safe filesystem for DOS. Try a rear USB 2.0 port rather than a front-panel connector or a hub, enable USB Legacy Support, and re-plug the stick after enabling CSM. Use the one-time boot menu key at power-on to see whether the stick appears as a legacy device. If it appears only as a UEFI entry, the image is not a legacy one.

A note on names

ASUS and MSI rename pages between generations, and the same option can move between Boot and Advanced. The descriptions above use the tab names that have stayed stable: Boot, CSM, Secure Boot, OS Type, Windows OS Configuration. Exact wording is not guaranteed, and no version number is implied.

Step by step

  1. Enter firmware setup. Restart and press the setup key at power-on (Del or F2 on most boards), then switch to Advanced Mode with F7 on ASUS.
  2. Enable CSM. On ASUS open Boot > CSM and enable it. On MSI open Advanced > Windows OS Configuration and enable CSM.
  3. Relax or disable Secure Boot. On ASUS set Secure Boot > OS Type to Other OS. On MSI set Secure Boot to disabled.
  4. Select the stick. Save and exit, re-plug the USB stick, open the one-time boot menu and choose the legacy entry for the stick.

Questions

Do I need to disable Secure Boot to boot DOS?
Yes. A DOS boot sector is unsigned, so the firmware will not start it while Secure Boot is on. Disabling Secure Boot and enabling CSM together is the usual combination.

Why is there no CSM option on my board?
The board is in UEFI-only boot mode. Switch the boot mode to CSM or legacy first, disable Fast Boot if the option stays hidden, then reopen setup.

Does the DOS stick show up as UEFI or legacy?
A correctly written DOS image is a legacy MBR device. It should appear in the legacy or CSM list, not under UEFI. If it appears only as UEFI, rewrite the image.
