Floppy images: .img, .ima and .vfd explained

A floppy image is a byte-for-byte copy of the sectors on a disk, with no container and no metadata. The extensions .img, .ima and .vfd all describe the same thing; the differences are historical and practical, not structural.

One format, three names

A raw floppy image holds the disk's data area in logical order: sector 0 first, then the rest of track 0, then head 1 of track 0, and so on. Nothing inside the file records the geometry, so the file size is the only hint. .img is the generic name, .ima is used by some emulators and imaging tools for the same raw layout, and .vfd (virtual floppy disk) comes from VirtualBox and a few other virtualisers. All three open in the same tools.

Standard geometries

Floppy formats are defined by cylinders, heads and sectors per track. The table lists the common PC geometries and the exact byte size each produces.

The K and M labels are approximate: a 1.44 MB disk holds 1,474,560 bytes, not 1,440,000.

Why 1.44 MB is exactly 1,474,560 bytes

Multiply the geometry: 80 cylinders × 2 heads × 18 sectors × 512 bytes = 1,474,560. Every factor is fixed by the standard, so the size is exact and every 1.44 MB image is that long. The same arithmetic gives 2,949,120 bytes for 2.88 MB, 1,228,800 for 1.2 MB, 737,280 for 720 KB and 368,640 for 360 KB. A file that is a few bytes off is either a different geometry or a damaged dump.

The boot sector and the 0x55AA signature

Sector 0 is the boot sector. The last two bytes of the 512-byte sector are 0x55 followed by 0xAA; firmware checks them before jumping to the code at offset 0. DOS itself does not need the signature once the loader is running, but a board's CSM and most imaging tools do. A system image also carries the BIOS Parameter Block in the first bytes of the boot sector, describing the geometry and the FAT layout. Without the signature an image may still contain files but will not boot.

Write protection and inspection

A real floppy has a physical write-protect tab; an image needs the equivalent at the filesystem level. Mark the file read-only when you keep a master copy, and write to USB or virtual media rather than editing the master. Images are made by reading the device sector by sector with a raw disk tool and inspected with a hex viewer: bytes 0–2 should be a jump instruction, 3–10 the OEM name, and 510–511 the signature. Comparing the file size with the table above is the fastest sanity check.

What you can do without a physical drive

DOSBox 0.72 mounts a floppy image directly and boots it, so an image can be tested without hardware. VMware and VirtualBox attach .img and .vfd files as virtual floppy drives and boot from them; VirtualBox is where the .vfd name comes from. To put the same image on a real machine, MBFUTool 2.0 for Windows x64 writes an MS-DOS image to a USB stick, and one of its four operations turns a disk or floppy into a .mbfu image. Images above 4 GB cannot be mounted in DOSBox 0.72, which is irrelevant for floppies but matters for hard-disk images.

Step by step

  1. Identify the geometry. Read the file size and match it to the table; 1,474,560 bytes is a standard 1.44 MB disk.
  2. Check the boot sector. Open the first 512 bytes in a hex viewer and confirm the last two bytes are 55 AA.
  3. Protect the master. Set the file read-only and work on a copy; never edit the only known-good image.
  4. Test before writing. Boot the image in DOSBox 0.72 or attach it as a virtual floppy in VMware or VirtualBox.

Questions

Are .img, .ima and .vfd the same format?
Yes. All three are raw sector dumps with no header. Use the extension your emulator expects; the bytes do not change.

Why is my 1.44 MB image 1,474,560 bytes?
That is the exact geometry product: 80 × 2 × 18 × 512. The label rounds the number.

Can I edit files inside an image without a floppy drive?
Yes, with an emulator or an image editor. Keep an untouched master copy read-only and edit a working copy.
