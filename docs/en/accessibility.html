Website accessibility

Statement dated 17 November 2026. Last reviewed on 17 November 2026.

We want the site to be usable with a keyboard, a screen reader, magnification and in high-contrast mode. Our benchmark is WCAG 2.1 level AA.

1. What has already been done

  • semantic markup: header, nav, main, footer, lists and tables with headings;
  • the “Skip to content” link is the first in the tab order;
  • a visible focus ring and full keyboard operation: the menu, the FAQ accordions and the cookie settings dialog close with the Esc key;
  • text contrast of at least 4.5:1, large text — 3:1;
  • text scales up to 200% without loss of content or horizontal scrolling;
  • the interface illustration has a text description for screen readers;
  • animations are disabled when the system “reduce motion” setting is on;
  • the language of the pages is marked with the lang attribute, and the English versions have their own;
  • the pages contain no flashing elements and no autoplaying video.

2. Known limitations

  • the DOSBox menu image is a stylised illustration, not an interactive element; all information about the menu items is duplicated in text;
  • article pages contain long texts; they can be navigated by headings;
  • third-party embeds (analytics) are enabled only with consent and do not affect the accessibility of the main content.

3. Compliance

This statement takes into account the European Accessibility Act (Directive (EU) 2019/882), applicable to online commerce from 28 June 2025, and the requirements for the accessibility of consumer information. We aim for level AA and remove barriers as they are identified.

4. How to report a problem

Write to sementsul.maksim@yandex.ru with the subject “Accessibility”: describe the page, what you were trying to do and which technology you used (screen reader, magnification, keyboard). We reply within 10 working days and try to remove the barrier within a reasonable time.

If the answer did not satisfy you, say so in a follow-up message to sementsul.maksim@yandex.ru — the request will go to the person responsible for the project.
