DOSBox mount and imgmount: folders, images and drives

DOSBox gives you a Z: drive with its own commands and nothing else. To reach real files you either mount a folder as a drive or attach a disk image. The two commands look similar and behave very differently, and mixing them up is the usual reason a program cannot find its files.

MOUNT: a folder becomes a drive

MOUNT maps a host directory to a drive letter inside DOSBox. Files are read and written directly on the host, so changes are visible immediately on both sides.

MOUNT C C:\DOSGAMES
C:

The first path is the DOS drive letter, the second is the host folder. Once mounted, C: switches to it and normal DOS commands work. A folder mounted this way is not a disk image: there is no partition table, no boot sector and no FAT16 volume of a fixed size. It is a window onto your file system.

IMGMOUNT: an image becomes a drive

IMGMOUNT attaches a disk image file. DOSBox reads the image as if it were physical media, which is what you need for bootable disks and for software that reads raw sectors.

IMGMOUNT A C:\IMAGES\BOOT.IMG -t floppy
IMGMOUNT C C:\IMAGES\DOS622.IMG -t hdd
IMGMOUNT D C:\IMAGES\CD.ISO -t iso

The -t parameter states the media type: floppy, hdd or iso. Getting it wrong produces a drive that mounts but cannot be read, because the geometry or sector size does not match. A floppy image is typically 1.44 MB, a hard disk image carries a partition table, and an ISO is a CD file system.

Why a mounted image is not a written USB stick

Mounting an image in DOSBox changes the image file on your host disk. It does not touch any USB stick. If you want the image on real media, it has to be written to the stick by a tool that writes raw sectors, and that is a separate step with its own risks: the target is erased, and the result depends on the BIOS being able to boot from it.

The [autoexec] section

Commands typed at the DOSBox prompt disappear when you exit. Put them in the [autoexec] section of dosbox.conf and they run at every start.

[autoexec]
MOUNT C C:\DOSGAMES
C:
SET PATH=C:\;C:\DOS

Keep the section short and put the mount first, because later commands depend on the drive existing. If a path contains spaces, quote it. A wrong path fails silently at startup, so test by typing the same MOUNT line by hand once.

The 4 GB limit

DOSBox 0.72 cannot mount images larger than 4 GB. A larger image may be created and written to a stick by a Windows tool, but it cannot be attached inside DOSBox 0.72 for testing or editing. Keep images at or below 4 GB, and prefer FAT16 sizes that DOS handles comfortably, which in practice means staying near 2 GB. Step by step

  1. Create a folder for your DOS files. Make a directory on the host, for example C:\DOSGAMES, and put the program files inside it.
  2. Mount it. Type MOUNT C C:\DOSGAMES at the DOSBox prompt, then C: to switch to the new drive.
  3. Or attach an image. Use IMGMOUNT with the correct -t type for a floppy, hard disk or ISO image.
  4. Make it permanent. Add the same commands to the [autoexec] section of dosbox.conf so they run at every start.

Questions

Can I write to a mounted folder?
Yes. MOUNT gives direct access to the host folder, so files created in DOSBox appear there immediately.

Why does my image mount but show no files?
The -t type is probably wrong, or the image is not a DOS file system. Check whether it is floppy, hdd or iso.

Does IMGMOUNT write to my USB stick?
No. It only reads and writes the image file on the host. Writing to a stick is a separate operation.
