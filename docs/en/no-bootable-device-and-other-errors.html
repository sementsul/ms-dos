“No bootable device”: fixing boot errors on modern PCs

The five messages below all mean the same thing at heart: the firmware looked for something bootable and did not find it, or found it and rejected it. The wording tells you which stage failed.

The messages, one by one

  • No bootable device — the firmware found no device with a valid boot record in the current boot mode.
  • Reboot and select proper boot device — the same failure with a prompt; often boot order or the stick's mode.
  • Non-System disk or disk error — a boot sector was found, but it is not a DOS system disk (no IO.SYS/MSDOS.SYS chain).
  • Missing operating system — the boot sector ran but the partition it points to has no system files or the active flag is wrong.
  • Invalid media type — the BPB or FAT type does not match what the loader expects; typical of a wrongly formatted or truncated image.

No bootable device, reboot and select proper boot device

These come from the firmware, before any DOS code runs. Either the boot mode does not match the image (UEFI firmware, legacy MBR image), or CSM is off, or the stick was not written as a bootable device. Check the one-time boot menu: a legacy image should appear as a legacy entry, not under UEFI. Try another port, preferably rear USB 2.0, and confirm the stick is not formatted as a UEFI-only device.

Non-System disk and Missing operating system

These come from a loader that did run. The boot sector is present and the signature is valid, but the system files are missing, the partition is not marked active, or the BPB describes a different geometry than the image actually has. Rewrite the image with a tool that writes the whole device, not a file copy, and check that the partition carries the active flag.

Invalid media type

The loader read the BPB and found a combination it cannot use: a FAT type that does not match the cluster count, a sector size other than 512, or a geometry field that contradicts the image size. This is common when a 1.44 MB image is written to a 2.88 MB geometry, or when an image was truncated during download. Compare the file size with the expected geometry first.

Step by step

  1. Read the message. Note whether it comes from the firmware (no device found) or from a loader (device found, files missing).
  2. Match the boot mode. Set the firmware to CSM or legacy for an MBR DOS image, and disable Secure Boot.
  3. Check the device. Confirm the image was written to the whole device, has an active partition and a 55 AA boot signature.
  4. Try another port. Move the stick to a rear USB 2.0 port, re-plug it, and use the one-time boot menu to pick the legacy entry.

Questions

Why does the stick boot on one PC and not another?
Boot mode and CSM differ between machines. A legacy image needs CSM on and Secure Boot off; a UEFI-only machine will not list it.

I wrote the image but get Non-System disk. Is the image bad?
Not necessarily. The boot sector was read, so the device is bootable; the system files or the active flag are the usual cause. Rewrite the whole device and check the partition.
