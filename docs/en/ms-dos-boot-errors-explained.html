MS-DOS boot errors explained

Each message names the layer that failed: the firmware, the boot sector, IO.SYS or COMMAND.COM. Read the wording carefully, because messages that look alike are fixed differently.

How to read these messages

A message from the firmware appears before anything else and mentions a device or a boot order. A message from IO.SYS means the boot sector ran but the system files were not found. A message from COMMAND.COM means DOS is running and only a command was wrong. If the same message returns after a rewrite, suspect the stick rather than the image.

Non-System disk or disk error

Cause: the boot sector ran, but IO.SYS and MSDOS.SYS are not on the volume - or the firmware booted a different device.

  • Rewrite the stick; the write operation copies the system files as part of the image.
  • Check the boot order and choose the stick explicitly.
  • If the message appears with no stick attached, the hard disk's boot record is damaged - a different repair.

Invalid media type

Cause: DOS read the partition table, but the boot sector describes a file system it does not know - usually NTFS or exFAT, sometimes a damaged FAT.

  • Recreate the stick as FAT16; Windows formatting it as exFAT is the usual origin.
  • If it used to work, the boot sector or FAT is damaged; rewriting is faster than repairing.
  • On a hard disk, back the data up before any repair tool runs.

Missing operating system

Cause: the master boot record found no active partition, or the active partition's first sector does not end with the 55 AA signature.

  • Check the partition table: exactly one primary partition should be active.
  • Rewriting the stick rebuilds the MBR, the partition table and the boot sector together.
  • If this follows a failed installation, the partition table may need rebuilding instead.

Cannot exceed 4GB for FAT16

Cause: the formatting step refused because the target is larger than FAT16 allows. This is a message from the tool, not from DOS, and it protects you from a stick that would not boot.

  • Use a stick of 4 GB or less.
  • Or create a FAT16 first partition of 2 GB and mark it active, as the FAT16 article describes.
  • Do not work around it with FAT32: MS-DOS 6.22 cannot read the result.

Bad command or file name

Cause: COMMAND.COM is running, so the boot worked; the command is not on the current drive, not in the path, or misspelled.

  • Check the spelling and the current drive letter.
  • Run dir to see what is there, and path to see where DOS looks.
  • Some commands are external files: without FORMAT.COM in the image, that command does not exist.

Write protect error

Cause: something prevents writes to the media - a physical switch on an SD card or adapter, a firmware lock on USB writes, or a Windows storage policy.

  • Check the switch on the card or adapter.
  • Try another port and another card reader.
  • In Windows, check the storage policy for the device and any policy applied to removable media.

Step by step

  1. Note the exact message. Write down the wording and whether it appears before or after the DOS prompt.
  2. Check the boot device. Open the boot menu, confirm the stick is booted, and pick the entry without the UEFI prefix.
  3. Rewrite the stick. Recreate it as FAT16 with the system files included; most of these messages disappear here.
  4. Test on a second machine. If it fails identically, the stick or image is at fault; if it boots, the firmware settings are.

Questions

Is "Non-System disk" a sign of a dead stick?
Not usually. The boot sector ran but the system files were missing. Read errors on several machines are a different problem.

Can I fix these errors from Windows?
Most of them, yes: rewrite the stick. Partition-table repairs on a hard disk are better done from DOS after a backup.

Why does "Bad command or file name" appear for an existing command?
Because it is on another drive or not in the path. Change to its directory, or add it to PATH in autoexec.bat.

Does the 4 GB message mean my stick is broken?
No. It means the stick is larger than FAT16 allows. Use a smaller stick or a FAT16 first partition.
