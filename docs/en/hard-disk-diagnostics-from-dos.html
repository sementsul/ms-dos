Testing hard drives and memory from DOS

DOS diagnostics talk to the hardware with no operating system in the way, which is exactly why they still find faults that Windows hides.

Why boot from DOS at all

DOS diagnostic tools reach the drive's SMART registers and issue raw read commands without a driver, a cache or a background service in between. That is why a drive that looks healthy in Windows can still fail an MHDD scan.

Start with SMART

Before any surface scan, read the drive's own counters. The attributes worth watching:

  • 05 Reallocated sectors - sectors the drive has retired. A growing count means the surface is going.
  • C5 Pending sectors - sectors that could not be read and await a decision.
  • C6 Uncorrectable sectors - reads that failed even after error correction.
  • C7 Interface CRC errors - usually a cable or port problem, not the platters.

A drive with reallocated sectors is not repaired by a scan. Copy the data first.

Surface scans: MHDD and Victoria

MHDD boots from its own media and works with ATA and SATA drives when the controller is in legacy or IDE mode. It scans block by block and shows response times, so slow areas appear before they become errors. Its ERASE command overwrites sectors and destroys data; the same is true of write and remap in Victoria.

Victoria exists in DOS and Windows versions and combines SMART reading, a surface scan and simple repair actions. Treat every repair action as destructive: a remap writes to the drive, and a failing drive may not survive it.

Memory: Memtest86+

Memory faults look like disk faults: corrupt files, random crashes, a DOS that will not load. Memtest86+ boots from USB or CD, writes patterns across RAM and compares what comes back. Run at least two full passes - one pass misses intermittent errors - and note the failing addresses.

  • Test with XMP or EXPO disabled first; an unstable memory profile is a common cause.
  • If errors appear, test one module at a time to find the faulty stick.

SeaTools for Seagate drives

Seagate's SeaTools has a DOS version that runs the vendor's short and long tests. The long generic test reads the whole surface and is the one that matters for a warranty claim, so keep the result. For other brands use that vendor's own tool.

When the tool cannot see the drive

Most DOS diagnostics expect the controller in IDE or legacy mode. With AHCI enabled the drive may be invisible to a tool that addresses legacy registers directly. The fix is in the firmware: set the SATA mode to IDE or Legacy, run the diagnostic, then put the setting back.

  • Check the cable and try another port before blaming the tool.
  • NVMe drives are not supported by these utilities; they need a different toolset.
  • A drive the firmware does not detect will not be detected by DOS either; see boot errors.

Image before you repair

Every repair action on a failing drive - remap, erase, low-level format - writes to the media. If the data matters, copy it to a different disk first and verify the copy; a dying drive may not survive a second attempt.

That gives you a verified copy to work from. It is not a forensic imager, and it is meant for DOS file systems.

Order of work

  1. Read SMART and write the numbers down with the date.
  2. Copy the data off, if the drive still reads.
  3. Run a read-only surface scan and note the slow blocks and errors.
  4. Decide: replace the drive, or repair it with the vendor's tool.
  5. Test the memory separately before blaming the disk for corruption.

Step by step

  1. Read the SMART data. Note the reallocated, pending and CRC counters before running anything that writes to the drive.
  2. Copy the data off. If the drive still reads, copy the important files to another disk before any repair.
  3. Scan the surface. Boot MHDD or Victoria, run a read-only scan, look for slow blocks and errors.
  4. Test the memory. Run Memtest86+ for at least two full passes to rule out RAM.
  5. Capture an image. For DOS media, create a .mbfu image first so you can work from a verified copy.

Questions

Does MHDD work with NVMe drives?
No. MHDD addresses ATA and SATA drives through legacy controller interfaces; NVMe needs a different tool.

How many Memtest86+ passes are enough?
At least two full passes. One can miss errors that appear only when the modules warm up or when a pattern repeats.

Is a surface scan safe for the data?
A read-only scan is. Erase, write and remap operations overwrite sectors, so copy the data first.

Will SeaTools work on another brand of drive?
It may detect it, but the tests are written for Seagate drives. Use the drive maker's own tool elsewhere.
