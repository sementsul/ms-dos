Secure Boot, UEFI and CSM: booting DOS on modern hardware

A modern PC boots DOS only when three independent conditions are met. Fixing one and expecting the other two to follow is why this takes an evening.

Three requirements, not one

A machine boots MS-DOS when the firmware can run legacy boot code, Secure Boot is not blocking it, and the stick carries a BIOS boot sector with an active FAT16 partition. These are separate switches in separate menus, and each failure looks different.

What UEFI expects

UEFI firmware looks for an EFI System Partition - a FAT32 partition with a bootloader in EFI/BOOT/BOOTX64.EFI - and runs that program. An MS-DOS stick has none of this: it starts with a 512-byte master boot record, which the firmware executes in 16-bit mode and which chains to the partition boot sector and then to IO.SYS.

A UEFI-only machine has nothing to run, so it skips the stick or lists it without a bootable image. The old BIOS path survives on most desktops as CSM, the Compatibility Support Module, which provides the interrupt services DOS expects.

What Secure Boot checks

Secure Boot verifies the signature of the next program in the boot chain against the keys stored in the firmware. DOS boot code is unsigned, so with Secure Boot on the firmware refuses it. Disabling the check does not enable legacy boot by itself.

Two notes. Some boards require Secure Boot off before CSM appears, so change them in that order. And Windows 11 requires Secure Boot, so put it back afterwards.

CSM, Legacy, or Boot Mode

Vendors name the same switch differently: CSM Support, Launch CSM, Legacy Boot, Boot Mode: Legacy, UEFI/Legacy Boot: Both. All of them mean "let the firmware run BIOS boot code". Some boards offer Other OS instead of a Secure Boot toggle, which switches off the signature check.

Not every machine has the option: most laptops sold after roughly 2020, and several desktop chipsets, ship without CSM. Without it DOS cannot boot; the alternatives are another PC or a virtual machine.

Vendors differ

Entry keys are consistent enough: Del or F2 on ASUS and MSI, Del on Gigabyte, F1 or F2 on Lenovo, F2 on Dell, Esc then F10 on HP. The rest is vendor-specific:

  • ASUS keeps it under Security or Boot as OS Type, where Other OS means unsigned; some boards hide it until an administrator password is set.
  • MSI puts it under Settings - Security, next to a Boot Mode selector.
  • Gigabyte often needs CSM Support enabled before Secure Boot can be changed.
  • Lenovo uses Secure Boot plus a separate UEFI/Legacy Boot setting; BitLocker may ask for its recovery key afterwards.
  • Dell has Secure Boot Enable and a Legacy boot option list, with a confirmation on exit.
  • HP asks for a four-digit code when you disable Secure Boot.

Wording changes between versions, so follow the labels, not a memorised path.

The stick must be written for MBR/BIOS boot

A stick prepared for UEFI - GPT partition table, FAT32, an EFI bootloader - is invisible to CSM. MS-DOS needs the opposite: an MBR partition table, one active FAT16 partition and a DOS boot sector. That is what MBFUTool writes, and what the USB guide describes. If a tool offers the choice, pick MBR/BIOS rather than GPT/UEFI.

What to check in the boot menu

  • Open the one-time boot menu (F12, F11, F8 or Esc) rather than changing the permanent order.
  • If the stick is listed twice, choose the entry without a UEFI: prefix.
  • No entry at all: enable USB boot, disable Fast Boot, and try a rear USB 2.0 port.
  • Still nothing: recheck CSM and Secure Boot, then try the stick on another machine.

Step by step

  1. Open the firmware setup. Press the vendor key: Del or F2 on most desktops, F2 on Dell, F1 or F2 on Lenovo, Esc then F10 on HP.
  2. Disable Secure Boot. Find Secure Boot under Security or Boot and set it to Disabled; on ASUS, OS Type: Other OS does the same.
  3. Enable CSM or Legacy boot. Turn on CSM Support, Launch CSM or Boot Mode: Legacy, depending on the label.
  4. Select the stick. Open the one-time boot menu and choose the USB entry without the UEFI prefix.
  5. Restore the settings. Re-enable Secure Boot and the TPM for Windows 11 once the DOS work is finished.

Questions

Can Windows 11 still boot with Secure Boot disabled?
An installed system usually starts, although Windows 11 requires Secure Boot as an installation requirement. Re-enable it afterwards.

My laptop has no CSM option. Is there a workaround?
Not for DOS. Without CSM the firmware only runs EFI programs, and MS-DOS has no EFI version.

Does a UEFI shell let me run DOS programs?
No. It runs EFI applications; it cannot execute real-mode DOS code or load IO.SYS.

Why does the same stick boot on an old PC but not a new one?
The old PC has a BIOS with CSM; the new one is UEFI-only or has Secure Boot on. The stick is fine.
