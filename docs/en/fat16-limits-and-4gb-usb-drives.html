FAT16 limits: why a DOS USB drive stops at 2-4 GB

The size limit is not a bug in the tool or in your stick. It comes from the number of clusters FAT16 can address and the largest cluster MS-DOS accepts.

One number: about 65,500 clusters

FAT16 stores the location of every cluster in a 16-bit field, so a volume cannot hold more than 65,524 clusters; a few values are reserved. The volume size is cluster size multiplied by that count: bigger clusters buy a bigger volume, at the cost of wasted space in every file.

Cluster size sets the ceiling

  • 512 bytes per cluster - up to 32 MB;
  • 2 KB - up to 128 MB;
  • 4 KB - up to 256 MB;
  • 8 KB - up to 512 MB;
  • 16 KB - up to 1 GB;
  • 32 KB - up to 2 GB, the largest cluster MS-DOS accepts;
  • 64 KB - up to 4 GB, for systems that accept 64 KB clusters, which MS-DOS does not.

Every file also wastes on average half a cluster: with 32 KB clusters, a thousand small files can burn tens of megabytes.

Where the 4 GB figure comes from

Formatting tools and the Windows format dialog will create a FAT16 volume of up to 4 GB using 64 KB clusters. A DOS stick made that way can be written, mounted and checked on a modern system, and then fail on the machine it was made for, because MS-DOS cannot read 64 KB clusters.

That is why the documented limit is "up to 4 GB, 2 GB in practice": two gigabytes is what a DOS-compatible layout with 32 KB clusters gives you.

What happens above that

Ask for a 16 GB FAT16 volume and one of three things happens: the tool refuses with a message such as Cannot exceed 4GB for FAT16, it silently formats FAT32 or exFAT, or it produces a volume DOS cannot read. The first is the honest outcome; the other two look like success until the stick is in the target machine.

FAT32 is no way out for MS-DOS 6.22, which cannot read it at all. Only the DOS 7.x line shipped with Windows 95 OSR2 and 98 understands FAT32.

Using a larger stick

  1. Create a primary FAT16 partition of 2 GB (4 GB at most) at the start of the stick.
  2. Mark it active; DOS boots from the active primary partition only.
  3. Leave the rest unallocated, or use it for a second partition DOS will never see.
  4. Format it as FAT16 and copy the system files, or let MBFUTool write your image to the stick.

DOS addresses the first physical disk and its first partition, so extra capacity is invisible. The write itself is described in the USB guide.

Why DOSBox 0.72 stops at 4 GB

The DOSBox build that ships with MBFUTool, version 0.72, cannot mount an image larger than 4 GB. An image past that size is usually FAT32 or a raw dump of a larger disk, and the mount code does not handle it. MBFUTool's .mbfu captures of DOS media stay inside the limit, and the program reports the problem instead of producing a broken image.

Practical checklist

  • 2 GB stick: the safest choice for MS-DOS 6.22.
  • 4 GB stick: works with 32 KB clusters; verify that DOS reads it.
  • 8 GB and larger: first partition 2 GB, active, FAT16.
  • File names: 8.3, Latin characters, shallow folder trees.
  • Volume label: Latin characters, no spaces.

Step by step

  1. Check the stick size. Anything above 4 GB cannot be one FAT16 volume; decide between a smaller stick and a small first partition.
  2. Create the first partition. Make a primary FAT16 partition of 2 GB at the start of the disk and mark it active.
  3. Format it for DOS. Use 32 KB clusters; 64 KB clusters give 4 GB, but MS-DOS will not mount them.
  4. Write and test. Write your image, boot the stick, and confirm that DOS reads the volume.

Questions

Can FAT16 hold a file larger than 2 GB?
No. The file size field is 32 bits, which caps a single file at 2 GB, and the volume cap arrives first.

Does MS-DOS 6.22 read FAT32?
No. FAT32 support arrived with the DOS 7.x line in Windows 95 OSR2 and Windows 98.

Is exFAT an option for a DOS stick?
No. MS-DOS has no exFAT driver and cannot read the volume at all.

Why does Windows show my 16 GB stick as 2 GB?
Only the first FAT16 partition is formatted; the rest is unallocated. That is the intended layout.
